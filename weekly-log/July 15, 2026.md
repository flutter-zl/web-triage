### #189275 — web_canvaskit_tests postsubmits recently became very flaky due to timeouts
- **Action**: triage (assign + correct the root-cause direction)
- **Priority**: P1 (keep)
- **Suggested assignee**: mdebbar
- **Labels to add**: triaged-web, browser: chrome
- **Reasoning**: P1 flake turning the tree red; belongs to test-infra owner.
- **Root cause**: The reporter blamed the Dart SDK roll `3c5c58d1cfd` (July 9, 12:56 EDT), but all 30 Dart revisions in that roll are CFE/analyzer/Service changes with **zero `dart2js` content**, so it can't slow a `dart2js`-compiled suite. The **Chrome 145 roll (#182861, commit `37b8446840a`)** landed 8 minutes later at 13:04 EDT and is the far better fit: it jumps the bots Chrome 125 → 145, rewrites the browser launch path in `packages/flutter_tools/lib/src/web/chrome.dart` (~194 lines), forces Linux headless software WebGL (`--use-angle=swiftshader --enable-unsafe-swiftshader`), adds a DevTools console/exception listener piping all browser output to runner stdout on every launch, and bumps skwasm from 2 → 8 shards. It explains why **both** CanvasKit and skwasm regressed (a `dart2js` regression could never affect skwasm). Corroborated by **#189471** (benchmark regression independently fingering the same Chrome 145 roll). Next step: diff LUCI per-step durations across the `37b8446840a` boundary to confirm whether the time is in compile, browser startup, or execution.

### #189451 — [vector_graphics] useHtmlRenderObject() doesn't catch engine surface-creation failures
- **Action**: triage
- **Priority**: P2
- **Suggested assignee**: harryterkelsen (engine surface-creation error handling)
- **Labels to add**: triaged-web, c: crash, e: web_canvaskit
- **Reasoning**: Reproduced crash on web; already carries `fyi-engine` and `fyi-ecosystem`, so keep team-web for the engine angle and let ecosystem handle the package guard. Not a top-tier crash (needs a simulated surface failure / real-world WebGL context loss), so P2.
- **Root cause**: Two layers. (1) Engine: on 3.44.x a WebGL surface-creation failure surfaces as a bare JS string instead of a structured `CanvasKitError` (regression from 3.38.x) — an error-quality regression. Engine fix = restore a typed error; package fix = catch and degrade gracefully.

### #188264 — flutter run web: redirect to nested OIDC route hangs; DDC library-bundle loader ignores <base href>
- **Action**: keep waiting (already `waiting for response`); mark web review done
- **Priority**: P2
- **Suggested assignee**: (blank — in Dart's court; `dependency: dart` already set, nshahan engaged)
- **Labels to add**: triaged-web
- **Reasoning**: Regression, has repro, but Dart team already asked for a slimmer/complete repro and it carries `waiting for response`. Dev-mode only (production `flutter build web` works), so P2. Related to #189432.
- **Root cause**: The DDC library-bundle module loader resolves per-library module URLs relative to the current document path instead of honoring `<base href>`, so on a nested route like `/auth/callback` it requests modules under `/auth/…`, where the dev server's SPA catch-all returns `index.html` (`text/html` + `nosniff`), which the browser blocks — `main()` never runs. The old single-bundle `main.dart.js` honored base href, hence the regression.
