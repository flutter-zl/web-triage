### #185327 - [web] Flutter Webapp on Mobile Device Chrome Browser unable to autofill with Chrome Password Manager
- **Action**: close as duplicate
- **Priority**: P2
- **Suggested assignee**: (blank — closing)
- **Labels to add**: `r: duplicate`, `triaged-web`
- **Labels to remove**: (none needed on close)
- **Reasoning**: Same symptom cluster as #162066 (Windows Chrome autofill failure) and #137760 (mobile Android Chrome autofill failure), and PR #184673 is already open and under review for that autofill path. The reporter acknowledges overlap with the existing issues. Close as duplicate and point at #162066 + #184673 so the fix there covers this report too.
- **Comment** (suggested):
  > Thanks for the detailed report. This looks like the same underlying issue as #162066 (Windows Chrome) and #137760 (mobile Android Chrome). PR #184673 is currently in review for that autofill path and should cover the mobile Chrome + Windows Chrome cases you're describing. Closing as a duplicate of #162066 — please follow along there, and feel free to reopen or comment on #162066 if the fix in #184673 doesn't address your case once it lands.
- **Root cause**: Chrome's password manager on mobile (and on Windows Chrome) fills the native `<input>` elements directly, but Flutter's text-input path on web relies on an offscreen hidden input that gets rebuilt across focus events; the rebuild discards any value Chrome wrote before Flutter's controller read it. The macOS-Chrome-works / Windows-Chrome-fails split matches the known focus/rebuild timing differences the autofill plumbing has on those platforms, which is exactly what #184673 is targeting.
