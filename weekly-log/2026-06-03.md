### #187307 - [Web] Hot Reload fails (404) with custom base href: DDC module loader requests from root, ignores base path
- **Action**: re-route
- **Priority**: P2
- **Suggested assignee**: (blank)
- **Labels to add**: triaged-web, team-tool, tool, platform-web
- **Labels to remove**: team-web
- **Reasoning**: This is a bug in the dev server hosted within `flutter_tools`, which is responsible for serving hot reload modules on web.
- **Root cause**: The DDC module loader requests updated JS modules from the root path instead of prepending the custom `--base-href` path, leading to 404s when a custom base href is served.

### #187212 - [wimp] Support non-chrome browsers with wimp

- **Priority**: P3
- **Suggested assignee**: harryterkelsen
- **Labels to add**: triaged-web, P3, engine, e: wasm, e: impeller, platform-web, c: new feature

### #187296 - [web] Chrome iOS zooming is broken
- **Action**: triage
- **Priority**: P2
- **Suggested assignee**: (blank)
- **Labels to add**: triaged-web, P2, framework, platform-web, browser: chrome-ios
- **Labels to remove**: (none)
- **Reasoning**: A layout scaling bug specific to Chrome on iOS when users increase or decrease the text zoom level; confirmed reproducible by mbcorona.
- **Root cause**: Chrome iOS handles text zoom differently than Safari iOS. Flutter's viewport meta tag or text measuring code might be miscalculating text bounds or scaling factors on Chrome iOS under text-zoom, leading to incorrect layouts.

### #187454 - [various] `invalid_runtime_check_with_js_interop_types` violations in web packages
- **Action**: triage
- **Priority**: P3
- **Suggested assignee**: mdebbar
- **Labels to add**: triaged-web, P3, c: tech-debt, package
- **Labels to remove**: (none)
- **Reasoning**: Technical debt issue tracking static analysis violations in several web plugins under the newly proposed Dart 3 linter rule.
- **Root cause**: The listed packages perform direct runtime checks (e.g. `is DOMException` or casts to Dart types) which violate the strict interop guidelines of `invalid_runtime_check_with_js_interop_types`.

### #187231 - [web] Hidden editing <input> ignores TextCapitalization — Chromebook OSK auto-capitalizes
- **Action**: triage (already re-routed)
- **Priority**: P2
- **Suggested assignee**: (blank — text-input team owns it)
- **Labels to add**: triaged-web
- **Labels to remove**: (none)
- **Reasoning**: The issue has already been routed to `team-text-input`. We just add `triaged-web` to close out web team's review of the `fyi-web` tag.
- **Root cause**: `DefaultTextEditingStrategy` (used on Chrome OS because it is detected as Linux) does not call `setAutocapitalizeAttribute` in `applyConfiguration`, unlike iOS/Android strategies. Writing `autocapitalize` in the base class would fix this cleanly.

### #187482 - web_dev_config.yaml proxy that works for js web does not work with --wasm flag

- **Priority**: P2
- **Suggested assignee**: (blank)

- **Root cause**: When `--wasm` is enabled, the `flutter_tools` dev server likely uses a different request routing or fallback middleware configuration (to serve COOP/COEP headers or wasm files) that intercepts API proxy requests and falls back to serving `index.html`.
